## 为什么要分层

"根据每次教学反馈自动改进"听起来无害，直接实现却会出事：

- **规则无限膨胀** —— 每次会话加两条，三个月后没人敢信也没人敢删
- **前后矛盾** —— "多举例子" 和 "别啰嗦" 同时生效
- **偶发被固化** —— 用户某天心情不好说"太啰嗦了"，变成永久规则
- **不可回滚** —— 直接改 SKILL.md，用户看不出哪句是谁加的、为什么加

所以进化必须**分层 + 带证据 + 可回滚**。

---

## 三层的边界

| 层 | 内容 | 频率 | 门槛 | 存在哪 |
|---|---|---|---|---|
| **L1 用户模型** | 学得快/慢、偏好例子类型、能接受的数学密度、语言习惯 | 每次会话 | 无，直接生效 | `profile` + `teaching_prefs(layer=L1)` |
| **L2 教学策略** | "对该用户，递归类概念用调用栈图示有效；俄罗斯套娃类比失败过" | 累积 | **≥2 次同向证据** | `teaching_prefs(layer=L2)` |
| **L3 skill 本体** | 修改 SKILL.md 的通用规则 | 罕见 | **必须用户确认** | SKILL.md / references |

**L2 是主战场。**绝大多数进化都应该落在这里，因为它足够具体（绑定到
domain 或 atom）、可验证、可单条删除。

**L3 不要自作主张改。**如果反复观察到某条通用规则有问题，向用户报告
并建议，让用户决定。这个 skill 的通用规则是用户自己设计的，模型单方面
改写它会破坏用户对系统的掌控感。

## 信号采集

### 显式信号（用户直说）

| 信号 | 指向 |
|---|---|
| "没听懂" | 讲解层级过高，或缺前置 |
| "太快了 / 慢一点" | 篇幅或节奏（写 L1） |
| "X 是什么意思" | 术语没铺垫，或前置缺失 |
| "能举个例子吗" | 讲解违反了"具体优先"，值得记 L2 |
| "这个我早就会了" | 库里 level 偏低，或路线出错 |
| "有没有更简单的说法" | 需要降维，且是可复用的 L2 线索 |

### 隐式信号（更可靠，因为用户不会为了礼貌而伪装）

| 信号 | 指向 |
|---|---|
| 检验失败率高 | 讲解无效，不是用户笨 |
| 同一处追问 ≥2 次 | 该处表述有系统性问题 |
| 回答变短、变敷衍 | 疲劳或失去兴趣，该收尾了 |
| 主动跳过 / 转话题 | 当前内容与他的目标不匹配 |
| 会话中断在某个 atom | 那个点值得单独复盘 |

### 失败教法同样要记

用 `--polarity fails`。**"什么无效"通常比"什么有效"更能提升质量**，
因为有效的教法有很多种，而无效的教法会被反复重犯。

```bash
learndb.py pref add --layer L2 --scope "domain:数学" --polarity fails \
    --rule "用'就像做菜'类比抽象代数，用户明确表示更混乱了" \
    --evidence "第7次会话，用户说'这个比喻反而让我更晕'"
```

## 证据门槛

L2 规则需要 **≥2 次同向证据**才从候选转为生效。`pref add` 用相同的
`--rule` + `--scope` 再调用一次就会累加证据并自动转正。

门槛的意义：**一次偶发反馈不该被固化成永久规则。**没有门槛的系统会在
几周内积累一堆互相冲突的规则，然后整个进化机制失去可信度。

候选规则（`active=0`）会一直挂着，直到被第二次证据证实，或被 `prune` 清掉。
用 `pref list --all` 能看到候选。

每条证据带时间戳和信号描述，存在 `evidence` 字段里——出问题时能查
"这条规则是哪次会话、因为什么加的"。

---

## 防膨胀

- **规则总数控制在 30 条以内。**超了就该合并同类项或删弱的。
- **90 天未被命中的 L2 规则自动降为候选**：`learndb.py pref prune`
- 用规则时调 `pref hit --id N`，让"哪些规则真在起作用"可观测。
  从不被命中的规则要么范围写错了，要么本来就没用。
- 合并前先看 `scope`：两条 scope 不同的相似规则可能都对，
  不要为了减少数量而过度泛化——过度泛化的规则等于没规则。

## 提炼：从具体记录长出认知画像

`teaching_prefs` 和 `misconceptions` 存的都是**具体**记录，只有在你查到对应的
`scope`/`atom` 时才会被用上。碰到一个全新领域、没有任何现成记录匹配的情形时，
这些积累完全帮不上忙——只能凭本能重新试错，跟第一次遇到这个用户没区别。
所以需要第三层：把同类具体记录**提炼**成一句概括的认知特征，写进 `profile`
（L1，每次 `context`/`status` 都自动带出来，不需要主动查）。

```bash
learndb.py distill      # 检测哪些类型攒够了、该提炼了
learndb.py profile --set "insight:<type>=<提炼出的一句话>"
```

`distill` 扫描所有 `concept_type`（来自生效的 pref）和 `error_type`（来自
误区），报出两种情况：**够阈值但还没有对应画像**，或**已有画像但之后又攒了
新记录**（画像过时）。输出里附带该类型下的全部原始记录，读完直接写 profile。

**为什么做成命令而不是写一句"记得定期提炼"**：同 CLAUDE.md 决策 18——纯文字
指令不可能被可靠执行。这个命令把"该提炼了"变成一个**能被算出来的状态**，
它自己不做提炼（那是判断性工作），但保证这件事不会因为没人想起来而永远不发生。
`distill` 已挂进完整版 checkpoint 流程，跟 `pref prune` 一样有稳定触发点。

**提炼出的画像要写成"该怎么教"，不是"用户是什么样的人"**：

| 坏 | 好 |
|---|---|
| "用户对统计概念理解较弱" | "教期望/长期平均这类整体量时，主动点出被忽略的低概率路径让他算进去" |
| "用户容易混淆量词" | "遇到存在性陈述，把原文量词措辞单独摘出来逐字对照，说明论证结构" |

左边无法执行，等于没写。**`pending` 为空时不要硬凑**——凑出来的画像是噪声，
而且会挤占每次会话都要加载的 `profile` 预算。

## 收尾流程

每次会话结束按顺序做：

```bash
# 1. 会话记账（摘要 ≤5 行，长了没人看）
learndb.py session close --atoms <slug...> \
    --summary "教了闭包，前置作用域探针未过，补了 3 分钟；transfer 题一次过" \
    --signals "用户对'词法环境'这个词卡了两次；代码例子比文字描述有效"

# 2. 挑出够格的信号写成 pref（不是每次都要写，没观察到就不写）
learndb.py pref add --layer L2 --scope "domain:JavaScript" \
    --rule "抽象术语先给代码再给名字，反过来会卡" \
    --evidence "第4次会话，'词法环境'卡两次，改成先看代码后秒懂"

# 3. 定期维护
learndb.py pref prune
learndb.py distill      # 报出该提炼成认知画像的类型，见上一节
learndb.py export
```

**不要每次都硬凑 pref。**没有观察到值得沉淀的东西就不写——
为了"有进化"而写的规则就是噪声。

## 好规则与坏规则

| 坏 | 为什么坏 | 好 |
|---|---|---|
| "讲得更清楚一点" | 无法执行，无法验证 | "JS 领域先给可运行代码，再给术语名" |
| "用户喜欢例子" | 太泛，等于没说 | "数学领域用几何直觉比符号推导先行更有效" |
| "别用类比" | 过度泛化，扼杀有用手段 | "抽象代数别用生活类比，用户反馈更混乱（2 次）" |
| "多检验" | 已经是 SKILL.md 的硬约束了 | —— 重复通用规则的 pref 不要写 |

好规则的三个特征：**可执行**（知道下次具体该怎么做）、
**有范围**（绑到 domain 或 atom）、**可证伪**（能观察到它是否有效）。
