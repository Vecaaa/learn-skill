## 第一决策：要不要联网

**这是最省时间的一步。**不做这个判断，这个 skill 会变成"每次都先搜十分钟"，
用户在你还没开口讲之前就烦了。

| 类型 | 例子 | 做法 |
|---|---|---|
| **稳定知识** | 数学、算法、经典理论、语言基础、物理直觉 | **直接开讲**，模型内部知识足够 |
| **易变知识** | 框架 API、版本差异、工具链、行业现状、价格/排名 | **必须联网**，且核对版本与日期 |
| **半稳定** | 最佳实践、生态选型、社区共识 | 先讲内部认知，标注"可能已变"，用户在意时再查 |

拿不准时的判断句：**"这个知识在两年前和现在会不一样吗？"** 会 → 查。

另外，用户处在"卡住了要马上继续"的状态时，不要中断去搜索。先用内部知识
把人推过这个坎，回头再补核实。

## 检索要拿到的三样东西

检索的产物**不是一堆链接**，是这三样：

### 1. 领域骨架

这个领域怎么切分，各部分的依赖顺序是什么。这直接变成 atom 依赖图，
用 `learndb.py add --prereq` 写进库。

### 2. 权威一手源

后面所有讲解的事实基础，写进 `atoms.source`。日后发现讲错了能回溯修正。

### 3. 常见误区表

新手在哪里翻车。**这个价值最高，而且最容易被漏掉**——它能让你在用户
掉进坑之前就提前拆解，也能拿来出高质量的 `debug` 检验题。

检索时明确地找这个：搜 "common mistakes"、"misconceptions"、"为什么…是错的"、
Stack Overflow 上该主题投票最高的困惑帖。

## 源的优先级

```
官方文档 / 规范  >  经典教材、大学课程讲义  >  高质量长文、维护良好的开源仓库
                 >  博客  >  论坛、问答  >  内容农场（不用）
```

补充判断：

- **教材/课程讲义**对"骨架"最有价值——它们已经替你做过依赖排序了
- **官方文档**对"当前正确的 API"最有价值，但通常不适合当教学材料（缺少动机说明）
- **论坛/问答**对"常见误区"最有价值——人们在那儿暴露真实的困惑
- 同一事实在两个独立源上对得上，才算核实过

## 路线怎么抄得又快又准

**不要让模型自己现编学习路线**——容易漏关键前置、也容易把顺序排错。

更可靠的做法：**找 2–3 个成熟的课程大纲 / 教材目录，取交集当主干、差集当选修。**

```
主干  = 所有大纲都有的（公认必需）
选修  = 只有部分大纲有的（按用户目标取舍）
砍掉  = 只有一个大纲有、且与用户目标无关的
```

然后按用户在第 0 步说的目标裁剪。"面试速通"和"做研究"从同一份交集出发，
裁出来的东西完全不同。

**大目标模式（跨月计划）额外多一步**：先查这个目标是不是已经有现成的
**阶梯式项目课程**（"build-your-own-X"系列，Karpathy 的 micrograd→nanoGPT 路径等），
有的话直接采纳/裁剪，优于自己拼大纲交集。这类现成路径通常本身就是一串递进的
小项目，天然适合切成 phase。具体判断标准和例子见 `domains.md` 的
"跨月大目标：先查现成的阶梯式项目课程"一节。

## 防幻觉护栏

教学场景下幻觉的后果比一般场景严重：**用户会把它当真、记住、写进数据库**，
污染是持久的，而且用户没有能力发现。

规则：

- 具体 **API 签名、数字、版本号、引用、人名年份** → 有来源，或明确标注"待核实"
- 讲到"某某说过""业界普遍认为"这类断言时，要么给源，要么降级成"我的理解是"
- 用户指出矛盾时**优先重新检索**，不要圆场。圆场会把一个错误变成两个
- 每个 atom 尽量填 `--source`，日后可批量回溯校正

**低置信度时的正确表述**：直接说"这一点我不确定，要么我查一下，要么你先按
这个理解继续，遇到冲突以文档为准"。这比含糊其辞有用得多。

## 需要登录的资源

**不要索取用户的账号密码，也不要代填密码字段。**这是硬边界，
与文档存放位置或是否加密无关。

真正的目标是"不用每次重新登录"，而登录态存在 cookie / session 里，不在密码里。
所以可行路径：

1. **持久化浏览器会话（首选）** —— 让用户**手动登录一次**。桌面端浏览器
   会保留登录态，之后访问同一站点直接是已登录状态，不需要再输密码。
   这一步做完，"自动化"的目标其实就达成了。
2. **用户粘贴内容** —— 付费墙 / 内网资料，请用户复制正文过来。
3. **换等价公开源** —— 绝大多数付费资料有公开替代：arXiv 预印本、
   官方文档、公开课、作者本人的博客版本。
4. **官方 API / token** —— 很多学术库和文档站有 API。凭据放系统环境变量或
   keychain，由脚本读取，模型看不到值。比模拟登录稳定得多，优先考虑。

会话过期的表现是访问返回登录页。此时**一句话提示用户去登录**，
不要反复重试或试图绕过。

## 站点注册表

记录哪些站点需要登录、会话是否还活着，避免每次都重复试错。
只存不敏感的元信息，**绝不存凭据**。

文件：`~/.claude/learning/sources.jsonl`，一行一条：

```json
{"domain":"ieeexplore.ieee.org","needs_login":true,"account_hint":"学校 SSO",
 "access":"browser_session","last_ok":"2026-07-20","note":"走机构代理才有全文"}
```

字段含义：

| 字段 | 用途 |
|---|---|
| `needs_login` | 直接决定走浏览器还是 WebFetch，省一轮失败 |
| `account_hint` | 提醒用户用哪个身份登录，**不是凭据** |
| `access` | `public` / `browser_session` / `api` / `paste_only` |
| `last_ok` | 太久没成功访问 → 会话可能过期，提前提示用户登录 |
| `note` | 该站的坑（有无全文、限速、地区限制） |

检索前扫一眼这个文件；成功访问后更新 `last_ok`。
